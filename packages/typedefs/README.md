# @labdigital/graphql-codegen-typedefs

[![npm](https://img.shields.io/npm/v/@labdigital/graphql-codegen-typedefs)](https://www.npmjs.com/package/@labdigital/graphql-codegen-typedefs)

A [GraphQL Code Generator](https://the-guild.dev/graphql/codegen) plugin that
generates a TypeScript module exporting your GraphQL schema as a `typeDefs`
document (parsed with `graphql-tag`).

This lets a GraphQL server import its schema as code instead of reading
`.graphql` files from disk at runtime, which is convenient when the server is
bundled or deployed without its source files. It implements the feature
requested in
[dotansimha/graphql-code-generator#3899](https://github.com/dotansimha/graphql-code-generator/issues/3899).

## Installation

```sh
pnpm add -D @labdigital/graphql-codegen-typedefs @graphql-codegen/cli graphql
pnpm add graphql-tag
```

The generated file imports `gql` from `graphql-tag`, so `graphql-tag` must be
a (runtime) dependency of your project.

## Usage

```ts
import type { CodegenConfig } from "@graphql-codegen/cli";

const config: CodegenConfig = {
	schema: "schema.graphql",
	generates: {
		"src/generated/typedefs.ts": {
			plugins: ["@labdigital/graphql-codegen-typedefs"],
		},
	},
};

export default config;
```

```sh
pnpm graphql-codegen --config codegen.ts
```

Then use the generated `typeDefs` to build your schema, for example with
`@graphql-tools/schema`:

```ts
import { makeExecutableSchema } from "@graphql-tools/schema";
import { typeDefs } from "./generated/typedefs";

const schema = makeExecutableSchema({ typeDefs, resolvers });
```

## Configuration

| Option | Type | Default | Description |
| ------ | ---- | ------- | ----------- |
| `extendSchema` | `boolean` | `true` | Print the schema definition as an extension, `extend schema { ... }`, instead of `schema { ... }`. |

## Example output

For this schema:

```graphql
type Query {
  product(id: ID!): Product
}

type Mutation {
  addToCart(productId: ID!, quantity: Int!): Cart!
}

type Product {
  id: ID!
  name: String!
}

type Cart {
  id: ID!
  totalItems: Int!
}
```

the plugin generates `src/generated/typedefs.ts`:

```ts
// This file is automatically generated by @labdigital/graphql-codegen-typedefs
import { gql } from "graphql-tag";

export const typeDefs = gql`
	extend schema {
		query: Query
		mutation: Mutation
	}

	type Cart {
		id: ID!
		totalItems: Int!
	}

	type Mutation {
		addToCart(productId: ID!, quantity: Int!): Cart!
	}

	type Product {
		id: ID!
		name: String!
	}

	type Query {
		product(id: ID!): Product
	}
`;
```

## Notes

- The schema is printed with `printSchemaWithDirectives` from
  `@graphql-tools/utils`, so directives on the schema and its types are kept.
  Types are sorted alphabetically.
- The schema definition (the root operation types) is printed as an extension,
  `extend schema { ... }`, which `graphql`'s `buildSchema` and
  `makeExecutableSchema` from `@graphql-tools/schema` accept as is, and which
  can be merged with other type definitions that define the schema. Set
  `extendSchema: false` to print a plain `schema { ... }` definition instead.
  Schema extensions cannot have a description, so the description of the
  schema (if any) is only kept with `extendSchema: false`. A schema without
  root types has no schema definition; nothing is extended then.
- Backticks in the schema (for example in descriptions) are escaped.
- The schema is written as a whole; there is no option to include or exclude
  types.
